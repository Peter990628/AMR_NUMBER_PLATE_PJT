# 허용 범위 안의 이상치와 3개 구간 중앙값 실험

2026-11-12 오프라인 실험이다. 사용자가 지적한 **“한 번 잘못 측정된 값이 15cm 허용 범위 안에 들어오면 어떻게 되는가?”**를 확인했다.

**결과:** 정지한 정답 구간에 한 번만 5·10·14cm 오류를 주면, 중앙값 방식은 이번 합성 입력의 출력 오류를 제거했다. 실제 저장 데이터에서도 출력 변화량이 감소했다. 하지만 연속 두 번의 오류, 계속되는 부분 관측은 해결하지 못했고, 재확인으로 출력 공백과 정상 변화에 대한 지연이 늘었다. 실험 도구만 추가했으며 운영 ROS 코드·설정·USD에는 적용하지 않았다.

## 비교한 세 방식

| 방식 | 원본 관측 판정 | 실제 출력 |
|---|---|---|
| 기존 운영 방식 | 실제 C++의 최근 관측 비교·3회 확인 | 현재 원본 후보 |
| 마지막 채택값 기준 | 이전 실험의 alpha=1 판정기 | 현재 원본 후보 |
| 중앙값 3개 | 마지막 채택값 방식과 동일한 원본 판정 | 최근 연속 채택 구간 3개로 재계산한 후보 |

세 방식 모두 기존 cap20 RANSAC/PCA와 min/max 끝점, 0.8m 연장·1.0m 이격 공식을 사용한다. 원본 관측 판정의 허용 차이는 후보 위치·바라볼 끝점 각각 XYZ 거리 15cm, yaw 3°, 입력 source-time 간격 0.35초다. 중앙값 방식의 원본 관측 판정이 마지막 채택값 방식과 모든 저장 프레임에서 일치함을 검사했다.

### 중앙값 구간 계산

1. 입력 시각의 정확한 TF로 구간을 `odom`에 놓는다. 구간 중심은 PCA의 inlier 평균 중심이 아니라 **관측 양 끝점의 중점**이다.
2. 원본 후보를 마지막 채택값 판정기에 넣는다. 현재 관측이 거절되거나 무효이면 해당 출력은 무효이고 중앙값 이력을 비운다.
3. 연속해서 채택된 구간 3개가 모이면 A/B 방향을 기하적으로 맞춘다. A/B는 차량 앞·뒤 의미가 아니다.
4. 가장 오래된 구간의 접선·법선·수직축으로 만든 국소 좌표계에서 중심과 방향 성분의 중앙값, 길이의 중앙값을 계산한다. 접선은 정규화하고 법선은 접선과 수직이 되도록 정리한다.
5. 하나의 구간을 `끝점 = 중심 ± 길이/2 × 접선`으로 재구성한다. 그 끝점에 기존 연장·이격 공식을 적용하고, 각 후보에서 끝점을 바라보는 yaw를 다시 계산한다.

후보 위치와 목표점을 제각각 중앙값 처리하지 않는다. 완성된 구간의 단위 방향·직교 관계와 후보의 연장/이격 거리를 유지한다. 고정된 전역 XYZ축에서 중앙값을 취하지 않고 구간의 국소 좌표계에서 계산하여, 좌표계를 함께 회전·이동했을 때의 일관성도 독립 테스트했다.

다른 관측들의 성분을 조합하기 때문에 재구성한 구간이 실제로 어느 한 시각에 관측된 구간과 정확히 같을 필요는 없다. 이는 평활화한 추정이며 새로운 정답 관측이 아니다. 출력마다 사용한 source timestamp 3개와 전체 시간 폭을 기록한다.

### 확인 횟수와 입력 소실

이 시험기는 보수적으로 **원본 3회 확인 후 채택된 구간 3개**를 모은다. 첫 채택 관측을 중앙값의 첫 입력으로 함께 쓰므로, 처음 유효 출력에는 기본적으로 **원본 관측 5개**가 필요하다. 기존 두 방식은 3개다. 이것은 이번 중앙값 실험의 추가 대기이며 기존 운영의 확인 횟수를 변경한 것이 아니다.

거절 한 번에도 중앙값 이력을 비우므로 정상 복귀 이후 다시 연속 채택 3개가 필요하다. 원본 판정기의 재획득, 시간 역행/중복, 좌표계·세션·후보 거리 설정 변경, 입력 간격 초과, wall-time 입력 중단에도 이력을 초기화한다. 구간 3개의 source-time 전체 폭은 0.35초 이내로 제한했다. 따라서 현재 10Hz source-time 자료에는 적용되지만, 예를 들어 5Hz에서는 3개가 0.4초에 걸쳐 들어와 출력되지 않는다. 다른 주기에 일반화하려면 이 조건도 다시 검토해야 한다.

명시적인 무효 입력이나 timeout 동안 과거 후보를 유효하게 출력하지 않았다. 하지만 현재 입력 자체가 유효한 실제 위치 변화에서는 중앙값이 이전 위치를 잠깐 출력할 수 있다. 아래 합성 시험이 이 지연을 확인한다.

## 정답이 있는 합성 실험

합성 입력은 스캔의 빔을 재현한 것이 아니라 **피팅된 관측 구간 단계의 입력**이다. 10Hz에서 정상 관측 20개로 준비한 뒤 변화 구간 50개를 평가한다. 오류 시험에서는 실제 구간의 정답은 고정하고 관측에만 오류를 넣는다. 실제 이동 시험에서는 정답과 관측을 함께 이동시킨다.

| 시험 | 기존 / 마지막 채택값 | 중앙값 3개 |
|---|---|---|
| 한 번만 5·10·14cm 오류 | 해당 오차가 출력에 남음 | 시험한 각 경우 출력 오차 0 |
| 연속 두 번의 14cm 오류 | 14cm 오류 출력 2회 | 14cm 오류 출력 2회, 시점이 1회 늦춰짐 |
| 실제로 10cm 이동 후 유지 | 즉시 반영 | 0.1초 뒤 반영; 첫 출력은 이전 위치 |
| 실제로 30cm 이동 후 유지 | 0.2초 후 출력 재개 | 0.4초 후 출력 재개 |
| 실제 구간이 0.1m/s로 이동 | 시험 입력에서는 오차 0 | 약 1cm 뒤처짐 |
| 실제 구간이 0.4m/s로 이동 | 시험 입력에서는 오차 0 | 약 4cm 뒤처짐 |
| 한 번만 끝점이 1.5m 짧아짐 | 거절; 마지막 값 방식은 0.1초 후 복귀 | 거절; 0.3초 후 복귀 |
| 계속 끝점이 1.5m 짧게 관측됨 | 짧은 구간을 결국 채택 | 짧은 구간을 결국 채택 |

5·10·14cm 시험은 구간 전체의 위치 이동과 한쪽 끝점만 이동시키는 경우를 각각 실행했다. 정상 두 관측 사이의 단일 오류를 제거한 것이며, 모든 현실 노이즈에서 0오차를 보장한다는 뜻은 아니다.

±10cm로 반복되는 오류에서는 기존 방식이 1/50개, 마지막 채택값 방식이 25/50개, 중앙값 방식이 1/50개를 출력했다. 마지막 채택값 방식의 25개 출력에는 모두 10cm 오류가 남았다. 중앙값 방식은 처음 1개 출력은 맞았지만 이후에는 세 연속 채택값을 모으지 못했다. **오차가 작은 출력만 남았다는 이유로 성공이라고 할 수 없으며, 출력 가용성이 사실상 사라진 실패 사례다.**

지속적인 1.5m 부분 관측에서는 기존/마지막 값 방식이 48/50개, 중앙값 방식이 46/50개의 잘못된 짧은 구간을 출력했다. 일관되게 잘못된 관측은 이 시간 필터들만으로 판단할 수 없다. 이 결과는 원래 세단의 실제 앞뒤 끝이 관측되었다는 증거가 아니다.

시간은 합성 입력의 source time 기준이다. 이동 속도는 `odom`에서 구간 자체가 움직이는 속도이며, 정지 차량을 보는 AMR의 주행 속도와 같은 뜻이 아니다. 반응 시작, 현재 정답에서 1cm·0.5° 이내의 출력 3회 확인, 위치·목표점·yaw 오차, 출력 변화, 채택 수를 별도로 기록했다. 무효 입력·source gap·시각 중복/역행·context 변경·wall timeout·yaw ±π 경계까지 총 22개 시나리오를 검사했다. 실제 ROS 타이머/통신 시험은 아니다.

## 저장된 실제 데이터 재생

네 캡처의 동일한 원본 스캔 389개를 실제 C++ cap20으로 다시 피팅했다. 관측 시각의 정확한 TF만 사용했으며 누락 TF를 최신 TF로 대체하지 않았다. 실제 저장 자료에는 끝점 정답이 없으므로 **채택률은 가용성, 변화량은 흔들림 지표**다.

| 캡처 | 기존 | 마지막 채택값 | 중앙값 3개 |
|---|---:|---:|---:|
| 주 데이터 | 90/118 | 110/118 | 97/118 |
| 평행 복귀 | 83/87 | 87/87 | 85/87 |
| +10° | 82/89 | 85/89 | 77/89 |
| −10° | 78/85 | 83/85 | 77/85 |
| 합계 | 333/379 | 365/379 | 336/379 |

주 데이터는 기록 시작 전 이력과 첫 TF가 없어 모든 방식을 index3에서 초기화하고 index4~121을 집계했다. 기존 판정의 이 118개 상태는 실제 기록과 모두 일치했다. 다른 세 장면은 index0 초기화, index2 이후 집계다. 중앙값의 추가 준비 시간도 제외하지 않고 포함했다. 원래 cap10 기록에서 유효했던 피팅 기하는 그대로 일치함을 확인했고, 이번 세 방식의 비교는 전부 cap20이다.

### 같은 시점끼리 비교한 출력 변화량

채택 수가 다르므로 각 방식이 출력한 아무 쌍이나 비교하면 선택 효과가 생긴다. 아래는 **세 방식 모두 연속된 두 입력에서 유효 출력한 동일한 쌍**만 비교한 값이다. P95는 값들을 크기순으로 놓았을 때 약 95%가 그 이하인 경계다.

| 캡처 | 공통 연속 쌍 | 기존/마지막 값 위치 변화 P95 | 중앙값 위치 변화 P95 |
|---|---:|---:|---:|
| 주 데이터 | 74 | 12.22cm | 5.24cm |
| 평행 복귀 | 78 | 11.54cm | 4.84cm |
| +10° | 73 | 12.49cm | 7.29cm |
| −10° | 70 | 11.38cm | 6.36cm |

주 데이터의 같은 74쌍에서 최대 변화는 14.98cm → 9.33cm였다. 중앙값 방식이 출력한 전체 연속 91쌍의 P95는 6.23cm다. 공통 74쌍의 5.24cm와 서로 다른 분모임에 유의한다. 보고서는 중간 무효 관측을 건너뛴 다음 출력 사이의 변화도 따로 기록한다.

현재 원본 관측과 중앙값 출력의 차이도 기록했다. 그 차이는 필터가 출력을 얼마나 바꾸었는지이지 정답에 대한 오차가 아니다. 연장·이격 거리, 끝점 재구성, 방향 단위 길이와 직교성 잔차는 모든 유효 출력에서 1e-9 미만이었다.

두 실제 부분 소실 관측(index16,115)은 세 방식 모두 무효였다. 마지막 채택값 방식은 index17,116에서 복귀했고 중앙값 방식은 index21,118에서 복귀했다. 중앙값 방식은 정상 구간을 다시 모으며 기다렸고, 첫 사례는 그 사이 다른 원본 관측도 거절되어 더 늦어졌다. source time으로 소실 관측 이후 약 0.5초와 0.3초다. 과거 기하를 계속 유효 출력하여 이 공백을 숨기지 않았다.

## 검증과 재현

독립 단위 테스트 22개가 통과했다. 기존 EMA/마지막 값 판정기 테스트 19개도 다시 통과했다. 새 테스트는 단일 오류 제거뿐 아니라 연속 오류 실패, 반복 오류 출력 중단, 지속 부분 관측 오채택, 실제 이동 지연도 명시적으로 검사한다. 3D 회전·이동 일관성, A/B 교환, 양의 거리, 기하 관계, 시간/설정 초기화, 복사 후 외부 변경의 영향도 포함한다.

```bash
cd ~/peter_pjt
python3 tools/test_candidate_median_experiment.py
python3 tools/evaluate_candidate_median.py \
  --output-dir local_artifacts/median_trial01
python3 tools/probe_candidate_median_dynamics.py \
  --baseline-binary local_artifacts/median_trial01/replay \
  --output-dir local_artifacts/median_trial01_dynamics
```

새 출력 경로를 사용한다. C++17 컴파일러, Eigen 헤더와 Python 표준 라이브러리로 실행하며 ROS나 Isaac Sim을 켤 필요는 없다. 기본 입력은 기존 네 로컬 캡처이고 평가기의 `--artifact-root`로 그 상위 경로를 바꿀 수 있다.

- `tools/candidate_median_experiment.py`: 구간 중앙값과 후보 재구성, 시간 상태 관리.
- `tools/test_candidate_median_experiment.py`: 독립 단위 테스트.
- `tools/evaluate_candidate_median.py`: 실제 스캔·C++ 기준 비교, 같은 시점의 출력 변화 통계.
- `tools/probe_candidate_median_dynamics.py`: 정답을 가진 합성 구간 비교.

최종 실제 데이터 결과는 Git에서 제외된 `local_artifacts/median_segment_experiment_2026-11-12/verified/report.json`, 합성 결과는 `dynamics_final/report.json`이다. 각 폴더에는 시각별 판정·출력·입력 식별자·사용한 과거 시각·기하 잔차 또는 정답을 담은 JSONL이 있다. 코드/입력 해시와 재현 컴파일 명령도 저장했다. `run01`과 `final`은 각각 양의 연장 거리 검증 보완 및 원본 판정 일치 assertion 추가 전 실행으로, 본 문서는 `verified`를 최종 실제 데이터 결과로 삼는다.

Python 처리 시간은 구간 변환·원본 판정·중앙값 재계산 부분의 오프라인 호출 시간으로만 기록했다. 실제 C++ 노드의 지연, 센서·TF·ROS 통신 비용 또는 실시간 처리 보장은 아니다.

## 판단

중앙값을 **출력할 구간에 적용**하면 이번에 문제 삼은 단발성 허용 범위 내 오류를 줄일 수 있었다. 기존 운영 방식과 비슷한 전체 가용성에서 실제 출력 흔들림도 줄었다. 그러나 반복 오류와 계속되는 가림을 해결하지 못하며, 마지막 채택값 방식보다 출력 공백이 많고 정상 변화도 늦게 반영했다.

따라서 이 방법은 후보를 안정화할 실험용 선택지로 남긴다. 실제 이동 목표를 확정하는 정책을 설계할 때는 정지 관측에서 허용할 흔들림, 재확인 동안 기다릴 시간, 관측 구간이 충분히 보이는지에 대한 조건을 함께 정해야 한다. 필터 하나로 올바른 차량 끝점이나 이동 가능한 목표를 보장한다고 해석하지 않는다.
