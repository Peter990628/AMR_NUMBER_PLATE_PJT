# 주변 점 지지를 이용한 끝점 추정 실험

2026-11-12의 오프라인 실험이다. **시험한 지역 지지점 방식은 기존 방식보다 후보 안정성이 나빠 운영에 적용하지 않았다.** ROS 노드·기본 설정·USD·실행 중인 프로세스는 변경하지 않는다.

## 구현

프로젝트 루트의 `tools/endpoint_support.py`는 기존 RANSAC/PCA 직선과 inlier 집합을 입력받아 다음을 수행한다.

1. 선택된 클러스터의 점들을 기존 직선 위에 투영한다.
2. 각 inlier 주변 최소 ±5cm 구간에서 실제 관측된 클러스터 점 중 inlier 비율을 계산한다.
3. 구간 안에 서로 다른 원본 빔의 inlier가 3개 이상이고 비율이 60% 이상이면 해당 점을 지지가 있는 점으로 간주한다.
4. 이 조건을 만족하는 inlier들의 양끝 투영 위치를 새로운 관측 끝점으로 사용한다. 충분한 지지가 없거나 길이가 0.5m보다 짧으면 무효로 반환하며, 이전 끝점으로 대체하지 않는다.

고정 구간 방식과 간격 적응 방식 두 가지를 비교한다. 적응 방식은 앞뒤 최대 4개씩의 **전체 관측 클러스터 점**에서 양의 투영 간격 중앙값을 구하고 그 3배로 반경을 늘린다. 반경은 최소 5cm, 최대 15cm다. 희박한 tail inlier만으로 간격을 추정하지 않는다. 거리와 입사각에 따라 점 간격이 달라지는 것을 일부 반영하지만, 완전한 센서 관측 모델은 아니다.

이 방법은 끝점 주변의 지지를 검사한다. 양끝 사이 모든 구간의 연속 관측을 보장하지 않으며, 누락된 스캔 구간을 복원하지 않는다. 결과는 **관측 범위**이지 차량 실제 앞뒤 끝의 정답이 아니다. 끝점을 바꾸면서 직선의 중심·방향·법선·inlier·RMSE를 다시 계산하거나 덮어쓰지 않는다. 원래 피팅 결과와 새로운 범위 진단은 별도 필드로 보관한다.

## 재현

ROS를 실행하거나 Isaac Sim에서 Play할 필요가 없다. 시스템 C++17 컴파일러와 Eigen 헤더, Python 표준 라이브러리를 사용한다.

```bash
cd ~/peter_pjt
python3 tools/test_endpoint_support.py
python3 tools/evaluate_endpoint_support.py \
  --capture local_artifacts/refinement_limit_live_2026-11-12/after_20 \
  --output-dir local_artifacts/endpoint_support_trial01 \
  --gate-start-index 3 --score-start-index 4 \
  --partial-indices 16 115
```

출력 디렉터리는 새 경로여야 한다. 원본 캡처는 Git에서 제외된 로컬 자료다. 다른 캡처를 사용할 때 초기화 인덱스와 알려진 부분 소실 인덱스도 그 캡처에 맞춰 지정한다. 인덱스는 `paired.jsonl`의 0부터 시작하는 행 번호다. `--partial-indices`는 통계의 구분에만 사용하며, 알고리즘 또는 판정기에 누락 정답을 알려주지 않는다.

`tools/endpoint_support_replay.cpp`를 실제 `scan_preprocessor.cpp`, `vehicle_side_estimator.cpp`, `candidate_stability.cpp`와 함께 컴파일한다. 모든 방법에 동일한 원본 스캔과 cap20 피팅 결과를 공급한다. 후보의 연장·이격 거리는 캡처의 값을 그대로 사용하고, 판정기는 기존 15cm·3°·3회 확인 조건을 사용한다. 기본 피팅·판정 설정의 자료를 대상으로 하는 평가기이며 임의의 다른 노드 설정을 자동 복원하지는 않는다.

관측 시각의 odom TF만 사용한다. 같은 epoch·frame·stamp의 입력과 출력이 대응하는지 검사하며 결측 TF를 최신 값으로 채우지 않는다. 후보 위치와 look_at 목표점을 모두 변환하여 실제 C++ 판정기에 넣는다. 각 방법은 같은 시작 행에서 빈 판정 상태로 시작하고 자기 방법의 후보 이력만 사용한다.

출력 파일:

- `fitted.jsonl`: 실제 C++ cap20의 전체 점·클러스터·inlier·직선 결과.
- `baseline.jsonl`, `fixed_support.jsonl`, `adaptive_support.jsonl`: 방법별 끝점, 양끝 축소량, 지지 진단, 고정 좌표 후보, 판정 결과.
- `report.json`: 채택 수, 이동량, 길이 축소, Python 계산 시간, 설정과 입력·코드 해시.

## 비교 결과

주 캡처의 첫 행은 TF와 기록 이전 후보가 없으므로 122건 전체에 대한 완전한 판정 재생은 불가능하다. 기록상 재확인이 시작된 index3에서 두 방법을 각각 초기화하고 index4~121의 **동일한 118건**을 평가했다. 기존 방식의 이 118개 판정은 실제 기록과 모두 일치했다. 따라서 아래의 90/118을 과거 실제 수집의 91/122와 같은 분모로 비교하면 안 된다.

| 주 데이터 지표 | 기존 양끝점 | 간격 적응 지지점 |
|---|---:|---:|
| 후보 채택 / 동일 평가 구간 | 90/118 (76.3%) | 57/118 (48.3%) |
| unstable 판정 / 동일 평가 구간 | 16 | 37 |
| 정상 연속 후보 이동 p95 | 14.98cm | 24.08cm |
| 정상 연속 후보 이동 최대 | 21.69cm | 36.82cm |
| 관측 길이 축소 평균 | 0 | 15.86cm |
| 관측 길이 축소 최대 | 0 | 34.76cm |

연속 이동량은 TF가 있는 캡처 전체 연속 쌍 중 알려진 부분 소실·복구 4쌍을 제외한 **116쌍** 기준이다. 길이 축소는 **122건** 전체 기준이며 실제 차량 길이에 대한 오차를 뜻하지 않는다. 두 부분 소실 스캔은 모든 방법에서 최종 후보 무효 상태를 유지했고, 약 1.5m의 구간 소실 문제를 이 방법이 해결하지는 못했다. 고정 ±5cm 방식도 채택 57/118로 동일하게 나빠졌다.

다른 세 저장 캡처에서도 파라미터를 바꾸지 않고 확인했다.

| 캡처 | 기존 방식 | 간격 적응 지지점 |
|---|---:|---:|
| 평행 복귀 | 83/87 | 63/87 |
| +10° | 82/89 | 44/89 |
| −10° | 78/85 | 55/85 |

다른 캡처는 index0에서 초기화하고 index2 이후를 평가했다. 당시 실제 노드는 cap10이었지만 **이번 비교는 양쪽 모두 cap20**이므로 당시 저장된 최종 판정과 다를 수 있다. 당시 유효했던 측면 기하는 그대로 일치함을 검사했다. 주 캡처와 이 세 캡처를 합쳐 389개의 대응 스캔을 처리했다.

## 해석과 한계

고립점만 줄이면 안정될 것이라는 가설은 이번 대표 구현과 데이터에서 지지되지 않았다. 직선과 inlier 포함 경계가 조금 변할 때 지역 비율의 통과 경계까지 바뀌어, 끝점이 더 안쪽의 다른 점으로 이동하는 것으로 해석된다. 단순히 점 수 조건을 추가하면 끝점 변동이 감소한다고 가정할 수 없다. 이 결과가 모든 다중 점 기반 범위 추정법이 실패한다는 뜻은 아니다.

합성 테스트 20개는 고립점 제거, 조밀한 실제 관측 경계 보존, 회전·이동 일관성, 먼 거리·비스듬한 입사의 희박한 샘플, 규칙적인 빔 누락, 부분 구간 소실, 잘못된 입력을 확인한다. 합성 테스트 통과는 실제 데이터의 성능 개선을 의미하지 않는다.

처리 시간은 Python 끝점 계산만의 호스트 시간이다. C++ 피팅·TF·후속 판정·통신을 포함하지 않으며, 운영 C++ 노드의 추가 지연이라고 해석하지 않는다. 다른 세 캡처는 병렬로 평가했으므로 그 시간 수치를 방법 간 성능 비교에 사용하지 않는다.

재현 자료는 `local_artifacts/endpoint_support_experiment_2026-11-12/`에 있다. 주 결과는 `after_20_final/report.json`, 다른 각도는 `parallel_return/`, `plus10/`, `minus10/`이다. `method_probe/`는 탐색용 보조 실험이며 본 표는 재사용 가능한 평가 도구와 실제 C++ 판정기의 결과를 사용한다.

현 시점에서는 기존 끝점 계산을 유지한다. 다음 진단에서는 원본 스캔 일부가 -1로 바뀌는 현상을 별도로 추적하고, 직선 피팅과 관측 범위 추정의 관계를 다시 검토한다.
