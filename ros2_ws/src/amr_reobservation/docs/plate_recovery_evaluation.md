# 이동 전후 번호판 판독 평가 도구 — 2026-11-19

이동 전후에 **동일한 간격으로 원본 카메라 영상을 수집**하고, 고정된 전처리와
PaddleOCR로 판독 결과를 자동 비교한다. 평가 결과를 로봇 정지·성공 판정에 연결하지 않는다.

## 구성

- `tools/capture_plate_evaluation.py`: 구독 전용 ROS 수집기. 기본 10초, 초당 2회로 20개 표본을 예약한다.
  기본 `first_raw`는 구간의 첫 신선한 원본, 선택 옵션 `first_pair`는 구간의 첫 정확한 영상·결과 쌍을 저장한다.
  검출 성공 여부나 점수로 사진을 선택하지 않는다.
- `tools/evaluate_plate_recovery.py`: 수집한 전후 자료를 같은 OCR로 평가하고 JSON, CSV, HTML을 만든다.
- `tools/plate_evaluation.py`: 정확한 타임스탬프 연결, 중복·무효화 처리, 집계, 전후 짝 비교.
- `tools/diagnose_plate_capture.py`: 별도 프로세스에서 원본·검출 결과·디버그 영상의 header를 감시해
  수집기만 놓친 결과와 양쪽에서 모두 보이지 않은 결과를 구분한다. 이미지를 저장하는 작업은 수집기만 수행한다.

이미지는 `/front_stereo_camera/left/image_raw`, 검출 결과는 `/plate/observation`이다.
양쪽의 **frame_id·stamp·해상도가 모두 일치**해야 검출 상자로 crop한다.
근처 시각이나 최근 상자를 가져다 붙이지 않는다. 원본 이미지에 상자·상태 글씨를 그리지 않는다.
`usable`이나 검출 점수 0.5를 조건으로 사진을 제외하지 않으며, 유효한 검출 상자가 있으면
`low_confidence`도 동일하게 OCR을 수행한다.

전처리는 전체 crop을 520×110으로 `INTER_CUBIC` 크기·비율 조정하는 방법으로 고정했다.
이 비율은 현재 합성 번호판 규격을 사용한다. 원근 보정이나 정답에 가까운 결과 재선택은 없다.
모델은 이전 실험의 `korean_PP-OCRv5_mobile_rec`과 동일한 파일·설정이며 해시를 확인한다.
정답은 추론 후 채점에만 사용한다. NFC·공백 정규화 외에 문자 치환은 없다.

## 기록하는 지표

- 예약 표본 수, 저장 이미지 수, OCR 시도 수, 전체 문자열 일치 수.
- **전체 일치 수 / 예약 표본 수**: 미검출, 이미지 누락, 검출 결과 누락, 입력 무효, OCR 오류도 분모에 포함.
- OCR을 실제 수행한 표본에서의 일치 비율: 위 지표와 별도로 표시.
- 최장 연속 정답 표본 수. 실패·누락·시간 구간 공백·입력 오류 이벤트가 있으면 끊는다.
  **초당 2회 뽑은 표본의 연속성이지 카메라의 모든 프레임 연속성은 아니다.**
- 이미지·crop·전처리 입력 해시, source header, 원래 검출 메시지, 검출/OCR 점수, 문자열, 처리 시간.
- 실제 검출 노드의 파라미터(조회 실패 시 빈 값과 실패 단계 기록), `/clock` 진행, odom 이동량, 오류 이벤트.

`not_detected`, `missing_image`, `missing_observation`, `missing_pair`, `input_invalid`, `source_mismatch`,
`resolution_mismatch`, `invalid_bbox`, `ocr_error`를 구분한다. 입력 끊김을 단순 미검출로 기록하지 않는다.
같은 source stamp의 타임아웃 무효화는 과거 결과를 취소하며, 중복 성공 메시지가 이를 되살리지 못한다.

전후 trial ID가 같아야 비교하며 표본 간격·기간, 입력 종류, 수신 스트림, 기록된 검출 파라미터가
다르거나 시계가 역행·중첩하면 비교 수치를 만들지 않는다. 원본 수집에서 한쪽 또는 양쪽 검출
파라미터 기록이 비어 있어도 `detector_parameters_unavailable`로 비교를 보류한다.
한쪽 입력이 전혀 없을 때도
이동 효과를 계산하지 않는다. 누락이 일부 있으면 예약 표본 분모는 유지하므로 수집 상태를 함께 봐야 한다.

## 실험 절차

Isaac Sim Play 및 기존 번호판 검출 노드를 유지한다. 수집 중 AMR은 정지 상태여야 한다.
전후 수집은 **같은 실행 세션**에서 수행한다. odom을 받을 수 있으면 수집 중 3cm 또는 2도 넘는
이동을 비교 오류로 표시한다. odom이 없으면 정지 상태를 자동으로 확인할 수 없으며 기록에 남긴다.
이 도구는 초기 접근, 재관측 후보 선택, 이동을 실행하지 않는다. 기존 이동 로직으로 이동한 뒤
정지·안정화된 상태에서 after 수집을 실행한다. 수집 완료 출력이 나온 뒤 다음 동작을 시작한다.

프로젝트 루트에서 ROS 수집 명령:

```bash
cd ~/peter_pjt
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp

/usr/bin/python3 tools/capture_plate_evaluation.py \
  --trial-id diagonal_01 --phase before \
  --sampling-mode first_pair \
  --output local_artifacts/plate_live_eval/diagonal_01/before

# 기존 재관측 로직으로 이동하고 정지한 다음 실행:
/usr/bin/python3 tools/capture_plate_evaluation.py \
  --trial-id diagonal_01 --phase after \
  --sampling-mode first_pair \
  --output local_artifacts/plate_live_eval/diagonal_01/after
```

각 수집은 연결 준비(최대 5초) + 기본 10초 + 검출 결과 대기 1초 + 파라미터 조회 시간이 걸린다.
준비 중 각 토픽이 실제 도착했는지와 대기 시간을 별도로 기록한다. 준비가 시간 내 끝나지 않아도
예약 표본을 없애지 않으며, 실제 도착하지 않은 데이터는 누락으로 남긴다.
입력 없는 경우에도 예약한 슬롯을 남기고 종료 코드 1을 반환한다.
영상은 실시간 저장하고, OCR은 수집 후 CPU 2스레드·주소 공간 상한 5GiB의 별도 환경에서 수행한다.

```bash
cd ~/peter_pjt
local_artifacts/paddle_ocr_validation_2026-11-19/venv/bin/python tools/evaluate_plate_recovery.py \
  --captures local_artifacts/plate_live_eval/diagonal_01/before/capture.json \
             local_artifacts/plate_live_eval/diagonal_01/after/capture.json \
  --expected 123가4567 \
  --output local_artifacts/plate_live_eval/diagonal_01/evaluation
```

생성물:

- `comparison.html`: 단계별 집계, 전후 변화, 모든 표본의 입력·판독 결과를 브라우저에서 확인.
- `frames.csv`: 표본별 결과를 표 계산 프로그램에서 확인.
- `report.json`: 모델·설정·출처·모든 결과를 포함한 상세 기록.
- `inputs.json`: 추론 전에 고정한 입력과 평가 설정.
- `*_crop.png`, `*_ocr.png`: 실제 사용한 crop과 OCR 입력.

출력 디렉터리는 새 경로만 허용한다. 반복 실험에는 trial ID와 디렉터리를 바꾼다.
모든 결과는 기존 git 제외 경로 `local_artifacts/`에 저장한다.

사용자가 연 실패 배치에서 현재 영상 3장으로 CFV 방향을 새로 추정하고, 현재 LiDAR 형상과

같은 시각의 검출 결과가 연결되지 않은 슬롯도 제외하지 않았다.

## 정지 상태 수집 진단 및 수정 — 2026-11-19

AMR을 움직이지 않고 별도 감시 프로세스와 수집기를 함께 실행했다.
초기 검출 노드는 꺼져 있어 기존 설정으로 다시 실행했으며, 이 작업에서 이동 명령은 발행하지 않았다.

첫 기준 시험은 원본 20장 중 결과가 연결된 것이 12장, 연결 누락이 8장이었다.
누락 8장 모두 독립 감시기의 `/plate/observation`과 디버그 영상에서도 같은 header를 찾지 못했다.
수집기만 결과를 놓친 사례는 발견되지 않았다. 독립 감시기 자체에서도 원본 114개 중 41개에
대응하는 검출 결과가 없었고, 구독자마다 받은 원본 프레임도 달랐다.

검출 입력은 `Best Effort / KeepLast(1)`이며 영상 처리 중 대기 영상을 모두 보존하지 않는다.
기준 시험의 처리 시간은 중앙값 약 81.6ms, 최댓값 약 117.4ms였다.
**각 구독자가 선택한 원본이 서로 다를 수 있다는 것은 확인했지만, 개별 누락을 검출기 대기열 생략과
전송 손실 중 하나로 확정하지는 못했다.** 이를 구분하려면 검출기 입력 콜백 단계의 추가 계측이 필요하다.

수집기는 다음과 같이 보완했다.

- `--sampling-mode first_pair`: 최대 2초·64MiB의 원본 버퍼에서 header가 정확히 같은 결과와 연결한다.
  0.5초 구간마다 처음 완성된 쌍을 저장하며 미검출·낮은 점수·입력 무효도 제외하지 않는다.
  가까운 시각의 다른 상자를 붙이지 않는다. 이미지가 와도 쌍이 없으면 `missing_pair`를 남긴다.
- PNG 저장은 별도 스레드에서 실행하고 작업 대기를 최대 4개로 제한했다.
  저장 중에도 ROS 콜백을 처리하며, 초과·실패는 오류로 기록한다.
- 결과 구독 깊이를 100으로 늘렸다. 연결 준비 시간을 측정 창과 분리했다.
- 슬롯별 원본·결과 수신 수, 완성된 쌍 수, 저장 시간과 선택 시간을 추가로 기록한다.
  파라미터 조회의 실제 성공 여부와 실패 단계 기록도 유지한다.

| 시험 | 저장·연결된 쌍 / 예약 표본 | 나머지 | 설정 기록 |
|---|---:|---|---|
| 기존 원본 우선 | 12/20 (원본은 20장 저장) | 결과 연결 누락 8 | 정상 |
| 쌍 우선 1회 | 20/20 | 없음 | 정상 |
| 쌍 우선 2회 | 19/20 | 쌍 미완성 1 | 정상 |
| 쌍 우선 3회 | 13/20 | 원본 누락 3, 쌍 미완성 4 | 정상 |
| 연결 준비 분리 후 1회 | 20/20 | 없음 | 정상 |
| 연결 준비 분리 후 2회 | 20/20 | 없음 | 정상 |

쌍 우선 3회차는 시작 후 약 3초 동안 토픽 발견·수신이 늦었다.
연결 준비 분리 후 마지막 두 시험은 총 40/40 쌍이 연결됐고, **모두 미검출 결과**였다.
6회 모두 실제 검출 파라미터가 기록됐으며 값이 같았다. 모든 창에서 정지 판정이 유지됐고
각 진단 종료 시 `/cmd_vel` 발행자는 없었다.

이 변경은 **정해진 시간마다 완성된 관측 쌍을 평가하는 방법**이다. 카메라 전체 프레임의 처리율이나
검출 정확도가 100%가 됐다는 의미가 아니다. 원본 우선과 쌍 우선은 서로 다른 표본을 고르므로
이전 OCR 15/20과 새 쌍 우선 비율을 직접 비교하지 않는다. 평가기는 수집 방식이 다른 전후 비교를 거부한다.
앞으로 이동 전후 모두 `first_pair`로 다시 수집하고, 전체 프레임 누락은 별도 진단으로 살핀다.
짧은 마지막 2회에서 누락이 없었다는 것으로 장기 무누락을 보장하지 않는다.

검증: 단위 테스트 12개 통과. 별도 ROS 도메인에서 미검출·점수 0.3·입력 무효를 각각
6/6 저장하고 원본 픽셀·정확한 header를 확인했다. 결과 토픽을 보내지 않은 시험에서는
6개 예약 슬롯을 누락으로 보존하고 종료 코드 1을 반환했다.

전체 원본·header·설정·진단 기록:
`local_artifacts/plate_capture_diagnosis_2026-11-19/summary.json` 및 각 시험 하위 폴더.

```bash
# ROS 환경 source 후 실행. 이동 명령을 보내지 않는다.
/usr/bin/python3 tools/diagnose_plate_capture.py \
  --sampling-mode first_pair --output local_artifacts/plate_capture_diagnosis/new_run
```

## 쌍 우선 방식으로 이동 전후 재검증 — 2026-11-19

수집 수정 후 실제 Play 배치에서 **왕복 1회**를 실행했다. 현재 영상 3장의 CFV 방향 추정과
현재 LiDAR 관측, 앞서 수동 확인한 차량 힌트로 후보를 새로 계산했다.
선택 후보는 `A1/view_C_45deg_2.0m`이며 출발 위치에서 목표 위치까지 거리는 약 1.07m였다.
이전 시험의 성공 좌표를 그대로 재사용하지 않았다.

이동 전후 모두 정지 상태에서 `first_pair`로 10초·2Hz·20개 슬롯을 수집했다.
미검출·낮은 점수도 포함했고, 영상과 검출 결과의 header가 정확히 일치하는 쌍만 연결했다.
40개 슬롯 모두 저장·연결됐고 수집 오류가 없었다. 검출 파라미터도 두 시점 모두 기록됐으며
값이 같아 자동 전후 비교 상태가 `paired`로 확정됐다.

| 단계 | 저장·연결된 쌍 | 검출 상태 | OCR 시도 | 전체 문자열 일치 |
|---|---:|---|---:|---:|
| 이동 전 | 20/20 | 모두 `not_detected` | 0 | 0/20 |
| 이동 후 | 20/20 | 모두 `low_confidence` | 20 | 20/20 |

이동 후 검출 점수는 **0.395~0.452**로 기존 `usable` 조건에 미달했지만, 유효한 검출 상자를
같은 고정 PaddleOCR에 전달하자 20개 모두 **`123가4567`**로 정확히 읽혔다.
전처리는 전체 상자 crop을 520×110으로 조정하는 기존 방식이며 원근 보정은 적용하지 않았다.
정답 문자열은 평가에만 사용했다. 최장 연속 일치는 20개 예약 표본이며 모든 카메라 프레임의
연속 판독을 뜻하지 않는다. 이동 전 결과는 OCR 오독이 아니라 미검출로 인한 OCR 미실행이다.

이번 결과는 **이 배치에서 이동 후 번호판을 실제로 읽을 수 있게 됐다**는 근거다.
다만 검출기의 `usable` 판정과 OCR 판독 성공은 구분해야 한다. 온라인 제어가 OCR 성공으로
종료하도록 연결한 시험은 아니며, 검출 임계값이나 자동 종료 정책도 변경하지 않았다.
단일 합성 차량·한 번의 이동 결과이므로 일반 성공률로 해석하지 않는다. 표본 선택 방식이 다른
이전 원본 우선 시험의 15/20과 직접 비교하지 않는다.

AMR은 출발점으로 복귀했고 최종 위치 오차는 **약 1.70cm**, yaw 오차는 **약 1.06도**였다.
이동 guard 종료 코드는 0이었다. 이번 실험에서 실행한 검출·후보 생성·제어 노드를 모두 종료했으며,
사후 확인에서 `/cmd_vel`, `/plate/observation`, `/reobservation/preview`, `/reobservation/request`
발행자가 없고 AMR 속도가 거의 0인 것을 확인했다.
