# CFV 사전학습 모델의 오프라인 시험

2026-11-18 재개 도구: `tools/capture_recovery_snapshot.py`로 현재 ROS 입력을
진단·저장하고, `tools/evaluate_cfv_snapshots.py`로 같은 시각의 CFV/TF/LiDAR를
평가할 수 있다. 제한 시험 연결은 문서 마지막의 「현재 Play 데이터로 재개」를 참고한다.

2026-11-13, 저장된 Isaac Sim 카메라 영상에서 차량 관측 방향을 추정했다.
추론 도구는 ROS에 연결하지 않으며 이동 후보·속도 명령을 발행하지 않는다.
첫 시험은 같은 세단의 제한된 후방 장면을 확인했으며, 후속 시험에서 정면과
양쪽 후방 대각선을 비교했다. 전체 영상 입력에서 정면을 후면으로 오인했지만,
앞뒤 어느 번호판이든 허용하는 목적에서는 180° 반전을 같은 차량 축으로 평가한다.
최종 축 평가와 LiDAR 기반 오프라인 후보 제안은 아래 「목적에 맞춘 재평가」 절을
우선한다. 11월 13일에는 오프라인 평가까지 진행했으며, 11월 18일에는 현재 ROS
입력으로 한 후보를 선택하고 제한 이동·복귀를 완료했다. 번호판 검출은 회복되지
않았다. 이는 지속 추론 서비스나 일반 주행 시스템의 검증은 아니다.

## 모델과 입력

- 공식 코드: <https://github.com/fort-cyber/car-orientation>
- 고정한 코드 commit: `780a898666e5678aa0bf0b3da292bc9aa8e2f473`
- 공식 README가 안내한 가중치: `convnext-multi-weak.pth`, 201,141,385 bytes
- SHA256: `26bd9e4eff8a4cfa3a264223ecced760f2fb3d1f29dc68f4e23b1b27babcd91d`
- 모델: `ConvNextSmallMultiModel`, `timm==0.6.12`; `pretrained=False`로 구성한 뒤
  `weights_only=True`로 읽어 `strict=True` 로드. 348개 state 항목 모두 일치.
- 시험 환경: torch 2.6.0+cu124, torchvision 0.21.0+cu124, CPU 4 threads.
- 원본 전체 영상 → OpenCV INTER_LINEAR 224×224 → RGB float32 /255.
  ImageNet 평균·표준편차 정규화, letterbox, 차량 crop을 적용하지 않았다.
  공식 준비 코드의 리사이즈와 시험 ToTensor를 따른다. 공식 코드가 리사이즈 후
  JPEG를 다시 저장하는 것과 달리, 이 도구는 추가 손실 압축을 하지 않는다.
- 분류 logits와 특징을 연결한 회귀 출력에 sigmoid를 적용한 뒤 360을 곱한다.
  보고서의 softmax 값은 보정된 정확도나 각도 신뢰구간이 아니다.

## 각도 기준

[논문](https://www.mdpi.com/2079-9292/12/24/4947)의 기준은
정면 0°, 차량 우측 90°, 후면 180°, 차량 좌측 270°다.
공식 `angle_dataset.py` 주석의 좌우 명칭은 논문과 반대지만 수치 구간은 같다.
공식 라벨 사진 0/45/90/135/180/225/270/315°를 직접 확인했으며 사진은 논문 기준과 일치했다.
추론 결과에는 혼동을 줄이기 위해 수치 각도와 class index를 기록한다.

`rear_deviation_deg`는 예측 각도와 180° 사이의 최단 원형 각도 차이다.
이 값은 로봇 yaw 명령이나 번호판 표면의 입사각이 아니다.
제자리 회전은 주로 화면에서 차량이 놓이는 위치를 바꾸고, 장착 오프셋에 따른
작은 카메라 위치 변화 외에는 차량 주변 관측 위치를 크게 바꾸지 않는다.

## 현재 PC에서 재실행

다운로드한 코드·가중치·timm 및 샘플 manifest는 위 로컬 경로에 준비되어 있다.
새 환경에서는 공식 저장소 README의 공개 가중치를 먼저 내려받고 동일 commit과
timm 버전을 준비한다. 이 도구 자체는 다운로드하거나 기존 환경을 변경하지 않는다.

```bash
cd ~/peter_pjt
python3 tools/probe_cfv_orientation.py \
  --upstream local_artifacts/cfv_test_2026-11-13/upstream \
  --checkpoint local_artifacts/cfv_test_2026-11-13/convnext-multi-weak.pth \
  --deps local_artifacts/cfv_test_2026-11-13/python_deps \
  --manifest local_artifacts/cfv_test_2026-11-13/samples.json \
  --output local_artifacts/cfv_test_2026-11-13/run_03
```

출력 디렉터리는 아직 존재하지 않는 경로를 사용한다. 실행 폴더가 프로젝트 루트가
아니면 `--image-root ~/peter_pjt`를 지정한다.
manifest의 `samples` 항목에 `id`, `image`, `group`을 넣으면 다른 저장 영상도 시험할 수 있다.
`cfv_label_deg`는 CFV 기준의 독립 정답이 있는 사진에만 추가한다.

```bash

```

원형 각도 경계와 공식 분류 구간 경계 테스트 3개가 통과했다.

원본 USD를 저장하는 동작은 이 촬영 도구에 없다.

실행 중 메모리 상한이나 자원 충분성 보장은 아니다. 실제 실행 환경에서 검사해야 한다.

`front_stereo_camera_left_optical`, 해상도는 1920×1200이며 캡처 동안 수신한
`/clock`도 43.450초에서 43.633초로 증가했다.

결과는 `local_artifacts/cfv_test_2026-11-13/live_fail_01/`에 있다.

## 기존 GUI에서 네 방향을 순차 촬영하는 도구

`capture_cfv_views_in_gui.py`는 이미 실행된 Isaac Sim의 카메라와 ROS 출력을
그대로 사용한다. 새 카메라·render product·시뮬레이터를 만들지 않는다.
AMR은 정지한 채 차량을 카메라 수평 전방 5.5m에 임시 배치하고,
차량 중심 기준 관측각 225° → 180° → 135° → 0°를 순서대로 만든다.
따라서 양쪽 후방 대각선, 후면 정면, 차량 정면을 비교할 수 있다.
이는 차량 방향 판별을 위한 영상 시험이며 AMR 경로·주행 검증은 아니다.
차량 회전에 따라 조명과 그림자의 상대 방향도 바뀐다.

1. 기존 `amr_camera_fail.usd`를 열고 Play를 유지한다.
2. ROS 환경을 설정한 터미널에서 아래 수집기를 먼저 시작한다.

   ```bash
   cd ~/peter_pjt
   source /opt/ros/humble/setup.bash
   ROS_DOMAIN_ID=0 RMW_IMPLEMENTATION=rmw_fastrtps_cpp \
     /usr/bin/python3 tools/collect_cfv_gui_views.py
   ```

3. 같은 Isaac Sim의 Script Editor에서 다음을 한 번 실행한다.

   ```python
   import runpy
   runpy.run_path('/home/peter-msi/peter_pjt/tools/capture_cfv_views_in_gui.py')
   ```

각 배치에서 최소 60회 앱 업데이트와 2초가 지난 후 수집기가 새로 구독해 한 장을
저장한다. 완료 확인 후 다음 배치로 넘어간다. 촬영 중에는 장면을 편집하거나
저장하지 않는다. 별도의 임시 session sublayer에만 차량 변환을 작성하고,
완료·오류 시 해당 레이어만 제거해 원래 차량 변환으로 복구한다.
사용자 Stop/장면 변경, 카메라 이동, 응답 시간 초과 시에도 중단·복구를 시도한다.

결과는 `local_artifacts/cfv_test_2026-11-13/gui_views_날짜_고유번호/`에 쓴다.
`state.json`의 `phase=complete`, `restored=true`와 `samples.json`의 `complete=true`를
모두 확인한 뒤 해당 manifest로 추론한다. 불완전 촬영은 완료 결과로 취급하지 않는다.
`geometric_reference_deg`는 모델 입력에 주지 않고 그림의 청록색 기준 화살표와
각도 차이 계산에만 사용한다. 네 장은 각 방향의 단일 표본이며 흔들림이나
다른 차량에 대한 정확도를 입증하지 않는다.

## 목적에 맞춘 재평가: 앞뒤를 구별하지 않는 차량 축

앞 또는 뒤 어느 쪽 번호판이든 읽으면 되는 재관측 목적에서는 180° 반전을 오류로
취급할 필요가 없다. 위의 정면→후면 오인은 **방향이 있는 차량 전방 추정**의 오류이며,
**차량의 길이 축**은 맞을 수 있다. 따라서 앞선 “정면 구분 실패 때문에 CFV 적용이
어렵다”는 결론을 그 자체로 적용하지 않고, 축 추정과 실제 후보 생성을 분리해서 평가했다.

축 오차는 `abs((prediction - reference + 90) % 180 - 90)`으로 계산한다.
이는 앞뒤만 동등하게 취급하며 옆면으로 90° 틀리는 경우는 그대로 큰 오류다.

| 촬영 방향 | 원본의 축 오차 | 10% crop의 축 오차 |
|---|---:|---:|
| 좌후방 | 7.83° | 10.78° |
| 후면 | 3.87° | 6.36° |
| 우후방 | 5.16° | 10.93° |
| 정면 | **3.74°** | **89.62°** |

원본 네 장의 축은 기준과 3.74~7.83° 차이였다. Crop의 정면 문제는 축 기준으로도
남는다. 이 네 장에는 순수 측면(90°/270°)이 없으므로 시뮬레이션의 모든 방향을
검증했다고 볼 수 없다. 기존 공개 학습 참고 사진 8장의 방향 구간 확인은 배선
검사이며 새로운 측면 영상에 대한 일반화 평가가 아니다.

### C 후보를 새 관측으로 실행하는 모드

#### 출발 전 준비와 시간 예산 보완

이동 전 여섯 차례 중단·보류한 기록을 보존한다. 각 시도에서 nonzero 명령은
0개였고, 실행된 독립 감시기는 모두 종료 코드 0으로 종료했다.

- `opposite_diagonal_trial/`: 감시기 시작 직후 `competing_cmd_vel_publisher`.
  당시 정확한 endpoint 이름은 저장되지 않아 원인을 확정할 수는 없다.
  실제 경쟁 발행자는 후속 검사에서 발견되지 않았다. DDS에서 명령 구독자와
  발행자 발견 순서가 다른 경우를 처리하도록 둘 다 확인할 때까지 최대 5초,
  정지 명령만 발행한다. 다른 발행자·중복 endpoint는 계속 즉시 거부한다.
- `opposite_diagonal_retry/`: 정지 기준 관측 중 일시적인
  `preview_contour_ambiguous_target`. 준비 중에는 알려진 윤곽 연관 실패를
  기다리되, 목표 확정 전 또는 준비 상태에서는 nonzero 명령 자체를 금지했다.
  세 번의 관측 확인, 입력·TF·시각·요청 유효성 검사는 유지한다.
- `opposite_diagonal_retry_02/`: 후보·관측 경로 간격은 통과했지만 시간 예산 부족.
  시뮬레이션/실제 시간 비율 약 0.247에서 왕복 예약 445초와 긴 관측 추가 예약
  46초, 준비 시간이 기존 전체 제한 480초를 넘었다. 2.0m 시험 전체 제한을
  540초로 늘렸다. 구간당 220초, 속도 0.07m/s·0.25rad/s, 목표 이동 1.75m,
  시작점 반경 1.85m, 관측 장애물 간격 1.2m, 시간 추정 여유 25%는 유지한다.
  감시기 전체 시간도 같은 제한을 적용하며 companion 요청은 600초다.
  이번 coordinator는 수집·추론 준비를 45초 이내로 제한한다.

- `opposite_diagonal_retry_03/`: DDS endpoint의 노드 이름이 임시로
  `_NODE_NAME_UNKNOWN_`인 상태에서 출발 전 중단했다. 이를 준비 중 대기
  상태로 취급하고, 정확한 감시기 이름이 확인돼야 시작하도록 보완했다.
  대기 중 정지 명령 및 5초 제한은 유지한다.

- `opposite_diagonal_retry_04/`: 무효 윤곽 preview의 기본 pose `(0,0)`가
  CFV 촬영 시점의 실제 pose와 다르다고 판정되어 `cfv_pose_changed_before_selection`.
  실제 odom 변화는 약 0.2mm였다. selector가 무효 관측으로 확인 횟수를
  초기화한 뒤, CFV 후보 생성기는 무효 preview를 좌표 검증·순위 계산 전에

- `opposite_diagonal_retry_05/`: 18초 안에 동기화·확인된 영상이 3장 중

#### 반대쪽 대각선 1회 이동 결과

새 영상 3장의 CFV 축 편차는 0.138°였다. 현재 관측에서 세 번 확인된
`A3` 표면 조준점 `(3.7152, 1.4537)m`을 사용했다. 새 출발점은 odom
`(0.9672, 0.1728)m`, yaw `0.147°`, 목표는 `(1.4156, 1.7333)m`, yaw `-8.990°`다.
목표 이동 거리는 1.624m이며, 이전 시험 목표·저장된 성공 지점을 사용하지 않았다.
새 odom 구간이므로 이전 배치의 odom 수치와 직접 차이를 비교하지 않는다.

| 관측 구간 | 수신 영상 | 상태 | 점수 중앙값 |
|---|---:|---|---:|
| 반대쪽 대각선 출발점 | 40 | 전부 `not_detected` | — |
| 새 목표, 시뮬레이션 10.017초 | 428 | 전부 `usable` | 0.568 |
| 이번 출발점으로 복귀 | 38 | 전부 `not_detected` | — |

목표에서 점수는 0.549~0.589, 검출 박스 중앙값은 약 251×84px였다.
검출/사용 기준 0.25 / 0.5 및 최소 박스 80×16px는 그대로 유지했다.
관측의 실제 시간은 약 38.35초, 수신 원본 시각의 최대 간격은 0.0667초였다.
관측 구간 내 무효·검출 끊김은 없었으며 정지 중 위치 변화는 0.342mm 이하였다.
저장 영상에서 초록 상자가 실제 번호판을 감싸는 것을 확인했다.

실제 도착 자세 기준 카메라→표면 거리는 2.003m, 추정 축 기준 관측각은
45.310°였다. 출발 전 관측 경로 간격은 2.088m, 이동 중 최소 간격은
전진 2.058m / 복귀 2.074m였다. 이는 관측된 점까지의 간격이며 전체 공간의
충돌 없는 주행을 보증하는 값은 아니다.

왕복·관측은 약 355초에 완료됐다. 복귀 오차는 1.62cm / 1.05°,
독립 감시기 종료 코드 0, 사후 `/cmd_vel` 발행자 0개와 거의 0인 속도를 확인했다.
AMR은 사용자가 설정한 **반대쪽 대각선 출발점**에 복귀해 정지했으며,
실험 중 USD 저장이나 장면 텔레포트는 하지 않았다.

사후 비교 영상의 CFV 출력은 129.50° → 160.66° → 129.48°였고,
후방 정면으로부터의 모델 추정 편차는 50.50° → 19.34° → 50.52°였다.
이는 새 위치에서 더 정면에 가깝게 보인다는 영상 관찰과 일치하지만 정답 각도는 아니다.
주황 화살표가 포함된 `comparison_arrows.png`와
`geometry_and_confidence.png`, 원본 시각으로 짝지은 영상·판정·TF·스캔·명령 기록을 보존했다.

이번 한 배치에서는 **새 방향/표면 추정 → 새 목표 생성 → 이동 → 검출 회복 유지 → 복귀**가
완료됐다. 직전 같은 쪽 시험의 중앙값 0.636보다 낮고 0.5 기준과의 점수 여유도 작다.
같은 차량의 반대쪽 한 사례이며, 여러 차종·조명·시작 위치에 대한 성공률이나
OCR 문자 판독 성공을 의미하지 않는다. 출발 전 중단 기록 여섯 건은 이동 실패율이나
번호판 검출 프레임 수와 합산하지 않고 준비 단계의 결함·수집 기록으로 별도 보존한다.
