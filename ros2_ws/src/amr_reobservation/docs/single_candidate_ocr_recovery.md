# 후보 한 곳을 사용하는 번호판 재관측

차량 근처에서 판독에 실패한 상태를 입력으로 받아, 현재 위치에서 OCR을 확인하고 필요하면
새 후보 한 곳으로 이동한 뒤 성공·실패를 반환하는 최소 통합 실행기다.
기존 실험과 달리 저장 자료의 사후 정답 비교가 아니라 **실행 중 OCR의 일관성**이 종료를 결정한다.
초기 차량 접근은 상위 로직의 역할이며 이 도구가 구현하지 않는다.

## 실행 흐름

1. 현재 위치에서 정지 안정화 후 4초·2Hz로 8개 이미지/검출 결과 쌍을 수집한다.
2. 고정 PaddleOCR로 읽는다. 이미 일관되게 판독되면 이동 없이 성공한다.
3. 실패하면 현재 정지 영상 3장으로 CFV 방향을 새로 추정하고, LiDAR에서 확인된 표면과
   결합해 45도·관측 거리 2.0m 후보 한 개를 계산한다. 저장된 성공 좌표를 재사용하지 않는다.
4. 기존 관측점 간격 검사·시간 예산·속도 제한을 통과하면 후보로 이동한다.
5. 도착 후 다시 정지하고 동일한 4초 수집/OCR을 수행한다.
6. 성공 또는 후보 소진 실패를 반환하고 **현재 위치에서 정지**한다.
   자동 복귀나 두 번째 후보 시도는 하지 않는다. 입력 오류는 `aborted`로 구분한다.

제어 프로세스는 OCR·CFV 자식 프로세스를 기다리는 동안에도 0 속도 명령, ROS 수신,
요청·센서·시간·정지 상태 검사를 계속 수행한다. 오래 걸리는 인식 계산이 제어 콜백을 막지 않는다.
별도 명령 guard의 0.35초 유효기간도 유지한다.

CFV 영상/관측 수집은 최대 30초이며 유효한 3개가 모이면 즉시 종료한다.
수집과 추론을 합친 상한은 60초다. 후보 선택은 최신 CFV 영상보다 이전인 대기열 관측을
제외하고, 이후 관측으로 연속 확인한다. 시각·TF·정지·요청·신선도 기준은 그대로 유지한다.

## 임시 성공 조건

다음 조건을 **관측 창의 마지막 3개 연속 표본**이 모두 만족해야 한다.

- 정확히 같은 원본 시각·frame·해상도의 이미지와 검출 결과를 사용한다.
- 숫자 2~3자리 + 한글 1자 + 숫자 4자리 형식의 동일한 문자열이다.
- 각 표본의 **OCR 점수**가 0.8 이상이다. 검출기의 `usable`이나 검출 점수 0.5는 요구하지 않는다.
- 서로 다른 원본 시각이며 인접 표본 간 원본 시각 차이가 1.5초 이하다.
- 인접 검출 상자의 겹침 비율(IoU)이 0.3 이상이다.
- 중간 미검출·입력 누락·오독·낮은 OCR 점수·무효화는 연속 횟수를 초기화한다.
  앞부분에서 3회 성공했어도 마지막에 실패했다면 성공으로 반환하지 않는다.

정답 문자열을 입력받지 않으며 문자 치환·정답 기반 재시도도 없다. 같은 오독이 반복되는 경우까지
배제한 것은 아니다. 위 값은 초기 실험 기준이며 모든 한국 번호판 형식이나 여러 차량을 지원하는
완성된 판독 정책이 아니다. 차량이 하나인 현재 장면에서 검증을 시작한다.

각 단계는 관측 창을 마친 다음 한 번의 OCR 작업으로 판정한다. 매 카메라 프레임마다 상시
OCR을 수행하거나 세 번째 일치 즉시 중간에 움직이는 구조는 아니다. 전처리는 기존 전체 상자
520×110 조정 방식이며 원근 보정은 사용하지 않는다.

## 실행

### Isaac Sim에서 한 명령으로 실험하기

빌드와 모델 준비가 끝난 이 노트북에서는 Isaac Sim에 `amr_camera_fail.usd`를 열고,
실패를 재현할 시작 자세에 AMR을 두고 Play한다. 일반 터미널 하나에서 실행한다.

```bash
~/peter_pjt/run_recovery_test.sh --execute
```

스크립트가 ROS 2 Humble과 프로젝트 작업공간을 불러온다. 기본 도메인은 0이고
기본 RMW는 Fast DDS다. 검출, 요청 발행, 후보 생성, CFV, 이동 제어, OCR, 센서 기록은
실행기가 관리한다. 현재 자리에서 이미 판독에 성공하면 거기서 종료한다.
같은 출발 조건으로 반복하려면 AMR을 실패 자세에 다시 놓고 같은 명령을 실행한다.
인자 없이 실행하면 모델과 설정 파일 경로를 확인한다.

빠르게 주행하려면 실행 명령에 `--speed fast`를 붙인다. 기본 속도는 최대
0.07m/s, 0.25rad/s이고 빠른 모드는 최대 0.14m/s, 0.45rad/s다.
두 모드 모두 목표 근처에서 감속하고 정지한 뒤 같은 시간 동안 관측한다.
`result.json`의 `speed`에 선택한 모드가 기록된다.

옆면만 보이는 시뮬레이션 배치에서 모서리로 한 번 이동하는 실험은 아래처럼 실행한다.

```bash
~/peter_pjt/run_recovery_test.sh --execute --corner-probe-once
```

기존 후보 대기가 끝난 뒤 최신 스캔 3개에서 옆면과 같은 쪽 끝점이 일관되게 보이면,
차체 옆을 따라 관측된 끝점보다 0.35m 지난 위치를 검토한다. 탐색 목표 거리는 최대
1.5m이고, 기존 세 LiDAR의 경로 간격 검사와 주행 가드를 적용한다. 도착 자세는
전방 카메라가 관측된 끝점을 향하도록 정한다. 이번 실행의 이동은 최대 한 번이며
정지 후 OCR 결과를 저장한다. 목표 근거는 `controller/selection.json`의
`corner_probe` 항목에 있다. 이어서 그 위치에서 기존 재관측 동작을 비교하려면
Play와 배치를 유지하고 기본 명령을 실행한다.

끝점을 0.15m 지난 위치로 같은 시험을 하려면 `--corner-probe-once 0.15`를 사용한다.
두 설정 모두 출발 위치에서 목표까지의 거리 상한은 1.50m다.

같은 옆면 배치에서 끝점을 30cm 더 지난 뒤 재조준하는 비교 실험은 아래 명령을 쓴다.

```bash
~/peter_pjt/run_recovery_test.sh --execute --speed fast --corner-probe-plus-30cm
```

이 실험은 현재 스캔에서 확인한 가까운 끝점을 기준으로 0.65m 지난 위치를 계산한다.
출발점부터 목표까지는 기존 근거리 재관측 범위인 1.75m 이내여야 한다.
옆면 근거를 3회 확인하면 한 곳으로 이동하고, 도착 후 정지 상태에서 OCR 결과를 기록한다.

기본 [차량 힌트](../config/camera_fail_test_hint.yaml)는 현재 장면의 `/World/sedan_car` 원점이다.
AMR의 시작 위치나 방향을 바꾸면 실행기가 차량의 `world` 위치를 새 `odom`으로 환산한다.
장면 자세와 로봇 TF가 같은 스캔 시각에 도착하면 요청을 발행한다.
수동 입력을 쓰는 장면은 `--mock-params /경로/차량힌트.yaml`로 별도 설정을 지정한다.
주행 전 확인 방법은 [차량 힌트 안내](fixed_vehicle_hint.md)에 있다.

터미널에 이번 실험의 폴더가 표시된다. 각 실행은 `local_artifacts/recovery_runs/` 아래
별도 폴더에 저장된다. Ctrl+C로 중단해도 실행기는 시작한 프로세스를 정리하고 결과를 기록한다.

| 확인할 내용 | 실험 폴더 안의 경로 |
|---|---|
| 성공·실패, 읽은 번호, 시작·종료 자세 | `result.json` |
| 이동 전후 카메라 사진과 OCR 판정 | `controller/before_capture/`, `controller/after_capture/`, `controller/before_ocr/report.json`, `controller/after_ocr/report.json` |
| 선택한 목표·조준점, 이동 중 자세와 명령 | `controller/selection.json`, `controller/events.jsonl` |
| CFV 방향 추정에 쓴 사진과 예측값 | `controller/cfv_capture/`, `controller/cfv_inference/predictions.csv` |
| 관측·전방·후방 LiDAR 원본, odom, 시계, TF | `sensors/` (ROS 2 bag). `result.json`의 `sensor_bag_finalized`로 기록 마무리를 확인한다. |

도달한 단계의 파일만 생성된다. 예를 들어 출발 위치에서 이미 읽혔다면 이동 후 사진은 없다.

### 직접 실행하기

현재 PC의 로컬 CFV/PaddleOCR 모델·환경 경로를 기본값으로 사용한다.
다른 PC에서는 `--config paths.json`으로 경로를 지정한다. 재학습·다운로드·외부 OCR API는 없다.
Python 실행기는 설치된 노드를 연결한다. mock 입력 노드·설정 파일을 변경했다면
`colcon build --symlink-install --packages-select amr_reobservation`으로 설치에도 반영한다.

```bash
cd ~/peter_pjt
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
export ROS_DOMAIN_ID=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp

# 경로와 설정만 확인. ROS 노드나 이동을 실행하지 않는다.
/usr/bin/python3 tools/run_plate_recovery.py \
  --mock-params ros2_ws/src/amr_reobservation/config/mock_recovery_request.yaml \
  --output local_artifacts/single_recovery_01
```

저장된 실패 배치에서 차량 힌트가 맞는 것을 확인하고 Play를 유지한다.
기존 검출·preview·속도 제어 노드는 종료한다. 실행기는 충돌하는 발행자를 발견하면 중단하며
외부 노드를 강제로 종료하지 않는다. 다음 명령은 실제 시뮬레이션 이동을 허용한다.

```bash
/usr/bin/python3 tools/run_plate_recovery.py --execute \
  --mock-params ros2_ws/src/amr_reobservation/config/mock_recovery_request.yaml \
  --output local_artifacts/single_recovery_01
```

`--mock-params`는 명시적인 수동 차량 힌트다. 기본 `anchor_base` 모드에서는 저장된 실패 배치와
다른 곳에 AMR을 놓았다면 `(3.5, 0.4)m` 힌트를 그대로 사용하지 않는다. 힌트는 시작 자세에서
한 번 `odom`으로 고정된다. AMR 시작 자세와 독립적인 차량 XY를 입력하려면
[고정 좌표 설정](fixed_vehicle_hint.md)의 `vehicle_hint_mode: fixed_frame` 파일을 같은 옵션에
전달한다. 다른 Play 구간에서 `odom` 좌표를 그대로 재사용해도 된다는 뜻은 아니다.
출력 폴더에는 mock과 preview의 600초 유효기간을 설정한 실행용 복사본을 저장한다.

상위 로직에서 실제 `RecoveryRequest`를 주는 경우에는 `--mock-params`를 생략한다.
요청에는 `odom` 좌표의 차량 힌트, 접근 pose, 요청/목표 ID, 유효기간 등이 필요하다.
실행 중 요청이 변경되거나 비활성화·만료되면 중단한다. 실제 상위 시스템과 연결한 검증은 아직 없다.

결과는 표준 출력과 `<output>/result.json`에 저장한다.

| 상태 | 의미 | 프로세스 종료 코드 |
|---|---|---:|
| `succeeded_without_motion` | 현재 위치에서 OCR 일관성 확인 | 0 |
| `succeeded_after_motion` | 후보 한 곳 이동 후 OCR 일관성 확인 | 0 |
| `candidate_exhausted` | 이동 후에도 판독 조건 불충족 | 2 |
| `no_candidate` | 제한 시간 안에 후보를 확정하지 못함 | 2 |
| `aborted` | 입력·시간·요청·경로·프로세스 오류 또는 사용자 중단 | 1 |

성공 여부는 `success`, 읽은 문자열은 `text`, 시도 수는 `candidate_attempts`다.
성공하지 못하면 `text`는 `null`이다. `request`에 상위 요청의 식별 정보를 보존한다.
이 단계의 인터페이스는 **일회성 CLI와 JSON 결과**다. ROS action/service 및 상위 호출 어댑터는
아직 추가하지 않았다. 실행기가 시작한 검출·preview·제어 프로세스는 종료 시 정리한다.
Ctrl+C로 중단할 수 있으며, 자동으로 출발점까지 복귀시키지 않는다.

상세 상태 전이는 `controller/events.jsonl`, 단계별 원본과 OCR 출력은
`controller/before_capture/`, `before_ocr/`, `after_capture/`, `after_ocr/`에 남긴다.
모든 실행 자료는 Git 제외 경로 `local_artifacts/`에 저장한다.

## 실제 Play 배치 통합 실행 — 2026-11-19

실제 배치에서 통합 명령을 실행했으며, 최종 결과는 **`no_candidate`**였다.
이동 전 8개 표본은 모두 `not_detected`였고 CFV 추정은 완료했다. 그러나 12초 선택 창 안에
후보를 3회 연속 확정하지 못해 약 54.7초 후 종료했다. 후보 시도는 0회이며,
**이동 → 이동 후 OCR 성공 경로 검증은 아직 남아 있다.**

실행 중 드러난 두 연결 문제는 수정했다. 먼저 18초 수집 창에서 영상/관측 묶음이 2개만
모이던 문제에 대해 위의 30초 상한·조기 종료를 적용했다. 다음으로 CFV 추론 중 쌓인 이전 시각
후보를 새 추정값에 결합하다 중단되는 문제를 수정했다. 관련 검사 35개와 저장 관측 재생을 통과했다.

최종 실행의 선택 구간 관측 37개를 원본 시각 기준으로 재생한 결과, 표면 구간의 분할/합침과
바라볼 지점의 변화 때문에 연속 지지가 최대 2회에 그쳤다. 이는 콜백 처리 시각까지 복원한
